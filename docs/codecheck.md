## 运行

安装方式见 [参与贡献](../README_CN.md#参与贡献)。`git commit` 自动检查暂存文件，也可手动运行。

```sh
pre-commit run codecheck --all-files
pre-commit run --all-files
```

脚本也可以在独立工具环境中运行，参数为要检查的文件。首次安装需要下载检查工具。

```sh
uv venv --python 3.12 .build/codecheck
uv pip install --python .build/codecheck --group lint
uv run --no-project --python .build/codecheck python -I scripts/check_codecheck.py path/to/file.py
uv run --no-project --python .build/codecheck python -I scripts/check_codecheck.py --list-rules
```

诊断显示文件位置、CI 规则编号和本地工具规则号。退出码 0 表示本地检查通过，1 表示发现拦截项，2 表示工具或输入读取失败。

## 提示与例外

负步长切片和海象运算符默认输出提示，需要将提示作为失败时加 `--strict`，默认提示规则配置在 `pyproject.toml` 的 `[tool.codecheck].advisory` 中。

```sh
uv run --no-project --python .build/codecheck python -I scripts/check_codecheck.py --strict path/to/file.py
```

自有检查支持同行、单条规则的例外。说明保留该写法的原因。

```python
reversed_values = values[::-1]  # codecheck: ignore[G.TYP.05] -- preserve the requested reverse ordering
```

Ruff 的例外继续使用其规则号，例如 `# noqa: N802`。`tests` 下允许测试断言，Pylint 保留项目的测试目录排除配置。检查过程保留源码和暂存内容。

## 维护

更新 `scripts/check_codecheck.py` 或相关检查配置后，须在同一次变更中核对并同步更新检查函数的 docstring、`scripts/codecheck_rules.json` 和本文覆盖表，确保覆盖状态、本地规则映射、检测范围和汇总数量一致。覆盖文档使用生成脚本时，也须同步维护生成脚本并重新生成文档。

自有检查按规则拆分为具名函数，在规则清单的 `local_rules` 中记录函数名，并在覆盖表中链接到实现；函数 docstring 标注规则编号和检测边界。输出文案统一维护在 `message` 字段中，检查脚本按规则编号读取。

CodeCheck 工具自身不单独编写或维护测试用例。
